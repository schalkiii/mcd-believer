# 营养配餐手册（热量 / 营养 / 指定热量套餐）

目标：结合餐品营养数据，帮用户**按目标热量或饮食偏好搭配一餐**，再无缝接入下单。

## 数据来源

- `list-nutrition-foods`：返回麦当劳常见餐品的**能量(kcal)、蛋白质、脂肪、碳水化合物、钠、钙**等营养数据。这是配餐的热量底座。
- `query-meals`：拿实际在售餐品与 `code`、现价（配餐后要下单必须有 code）。
- `query-meal-detail`：套餐子项与可替换项，用于在热量约束下做替换。

## 配餐流程

1. 明确目标：用户给的是**总热量上限**（如"500 大卡以内"）还是**偏好**（低卡/高蛋白/不吃辣）。两者都满足最佳。
2. `list-nutrition-foods` 拉营养表，按目标热量筛选候选餐品。
3. 组合搭配（控制总量与多样性）：
   - 主食（汉堡/卷）提供蛋白质与饱腹；
   - 小食分量控制（薯条/鸡块热量密度高，少放）；
   - 饮品优先无糖/美式；甜品按需。
   - 累加各品能量，逼近但不超过目标值；给出一餐 1–2 套候选方案。
4. 用 `query-meals` 核对候选在售并取 `code`；需要换子项用 `query-meal-detail`。
5. 用户选定 → 接 `references/ordering.md` 算价下单（如同时想省钱，叠加 savings.md）。

**确定性实现**：`scripts/solver.py` 支持预算 × 热量双约束组合枚举（热量缺失的餐品自动剔除，拒绝估算），输出最饱/最省/最均衡三套方案；真实链路中把 MCP 返回的菜单+营养表归一化后喂给它即可。离线试跑：`python scripts/solver.py solve --budget 40 --kcal 800`。

## 输出建议

给出方案时列明：**每样餐品的能量 + 本餐合计能量 + 蛋白质/脂肪/碳水概览**，并说明与目标热量的关系（"合计 470 kcal，低于你设的 500"）。数据一律来自 `list-nutrition-foods` 的返回值，不要凭记忆报营养数值。

## 注意

- `list-nutrition-foods` 的 `data` 为整体字符串负载，解析出每餐品字段后再用于计算；找不到某餐品营养值时如实说明，不要估算冒充实测。
- 营养建议仅供日常参考，不做医疗/减脂承诺。

## 健身进阶玩法（数据同样只来自 list-nutrition-foods）

- **蛋白质性价比榜**：按 `蛋白质g ÷ 现价(元)` 降序排列在售高蛋白品（来自 query-meals 价格），报"每元蛋白"数值；用户问"增肌吃什么最划算"直接给榜单 Top3 + 一份实价组合。
- **运动后窗口餐**：用户说"刚练完/待会去练"时，优先组合"高蛋白 + 适量快碳（饮料/薯条）"，热量目标按训练强度上下浮动；提醒 30–60 分钟内进食更佳，但不作医疗断言。
- **减脂一餐**："今天中午控制住了"类需求 → 给定热量带（如 450–550 kcal）取逼近上限但不超过的方案，同时用预算约束交叉筛（接 ordering.md 指定预算求解器）。
- **早餐档位**：7:00–10:30 早餐时段（以 query-meals 分类为准）优先"卷/麦满分 + 咖啡/豆浆"低卡组合；用 `now-time-info` 判断当前是否在早餐供应窗口。

## 特殊人群白名单（钠/糖/热量阈值）

用户表明高血压/糖尿病/肾病/孕妇/儿童/老人/健身/减脂等身份时：
1. 先要目标阈值（用户没给就用保守默认：全天钠 <2000mg、添加糖限量、单餐热量目标），并声明仅供参考、遵医嘱。
2. 用 `list-nutrition-foods` 的钠/能量/碳水字段对候选餐品打分，输出"白名单（可吃）/ 改配（减份量、换无糖饮、往小份移）/ 黑名单（本轮避开）"三档。
3. **量化改配**：不只说"少吃"，而是给替换方案与原/新数值对比（"薯条小份换玉米杯：热量 220→约90 kcal，钠 xx→xx mg"，数值均来自工具返回）。
4. 忌口（不吃辣/不吃香菜酸黄瓜等）写入 profile.md，后续会话自动生效。
