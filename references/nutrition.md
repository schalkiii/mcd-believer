# 营养配餐手册（热量 / 营养 / 指定热量套餐）

目标：结合餐品营养数据，帮用户**按目标热量或饮食偏好搭配一餐**，再无缝接入下单。

## 数据来源

- `list-nutrition-foods`：返回麦当劳常见餐品的**能量(kcal)、蛋白质、脂肪、碳水化合物、钠、钙**等营养数据。这是配餐的热量底座。
- `query-meals`：拿实际在售餐品与 `code`、现价（配餐后要下单必须有 code）。
- `query-meal-detail`：套餐子项与可替换项，用于在热量约束下做替换。

## 配餐流程

1. 明确目标：用户给的是**总热量上限**（如"500 大卡以内"）还是**偏好**（低卡/高蛋白/不吃辣）。两者都满足最佳。
2. `list-nutrition-foods` 拉营养表，按目标热量筛选候选餐品。
3. 组合搭配（控制总量与多样性）：
   - 主食（汉堡/卷）提供蛋白质与饱腹；
   - 小食分量控制（薯条/鸡块热量密度高，少放）；
   - 饮品优先无糖/美式；甜品按需。
   - 累加各品能量，逼近但不超过目标值；给出一餐 1–2 套候选方案。
4. 用 `query-meals` 核对候选在售并取 `code`；需要换子项用 `query-meal-detail`。
5. 用户选定 → 接 `references/ordering.md` 算价下单（如同时想省钱，叠加 savings.md）。

## 输出建议

给出方案时列明：**每样餐品的能量 + 本餐合计能量 + 蛋白质/脂肪/碳水概览**，并说明与目标热量的关系（"合计 470 kcal，低于你设的 500"）。数据一律来自 `list-nutrition-foods` 的返回值，不要凭记忆报营养数值。

## 注意

- `list-nutrition-foods` 的 `data` 为整体字符串负载，解析出每餐品字段后再用于计算；找不到某餐品营养值时如实说明，不要估算冒充实测。
- 营养建议仅供日常参考，不做医疗/减脂承诺。
